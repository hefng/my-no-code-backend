## Why

当前代码质量检查节点可能反复触发修复与复检流程，在质量结果长期不达标或结果异常时存在无限重试风险。需要引入明确的最大重试次数限制，保证工作流可终止并避免资源被持续占用。

## What Changes

- 为代码质量检查流程增加可配置的最大重试次数（例如通过 `WorkflowContext` 或配置常量控制）。
- 在每次质量检查失败后累计重试次数，并在达到上限后停止继续重试。
- 达到重试上限时写入可观测的状态与日志，标记当前流程进入“重试耗尽”分支，避免继续循环。
- 保持现有成功路径不变：在质量检查通过时正常进入后续节点。

## Capabilities

### New Capabilities
- `code-quality-check-retry-limit`: 为代码质量检查过程提供重试上限控制、计数与终止行为，防止死循环。

### Modified Capabilities
（无）

## Impact

- 后端工作流节点：`CodeQualityCheckerNode` 及其关联路由判断逻辑（若存在条件边/下一节点选择逻辑）。
- 工作流状态模型：`WorkflowContext` 可能新增重试计数与上限字段。
- 日志与可观测性：新增重试计数和上限触发日志，便于排查质量检查未通过场景。
